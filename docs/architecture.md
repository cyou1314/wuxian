# 架构设计（草案，2026-10-18）

## 形态二选一（待用户拍板）

- **A. Web 应用（推荐）**：React Flow 画布前端 + 后端服务；账号 / Cookie 登录、
  多账号额度调度都在后端；执行层独立。
- **B. Electron 桌面（对标 Deck）**：天然带已登录页面上下文，签名问题自动消失；
  但分发 / 更新 / 多端成本高。

## 模块

1. **auth**：Dola 账号登录（豆包账号体系）+ Cookie 登录（粘贴 session cookie）。
   Cookie 加密存储，不进日志、不进仓库。
2. **accounts**：多账号池，每个账号独立 cookie / 会话。
3. **quota（额度控制，核心差异化）**：
   - 从提交返回的 SSE 配额文本解析「消耗 X 个 / 今日剩余 Y 个」（无独立配额 API）
   - 每账号：剩余额度、日消耗、告警阈值；额度耗尽自动停用该账号
4. **scheduler**：任务按账号剩余额度分配（剩余最多优先 / 轮询）；
   额度耗尽自动切号；排队与失败重试。
5. **executor**：Dola 调用执行层。
   - 硬约束：必须跑在「已登录真实页面上下文」（Electron webview / 真实浏览器）
     或「家宽出口」；VM 机房出口裸调写入接口会被 `710022002` 拦截。
   - 链路：`skill/pack` → `/chat/completion` → 轮询 `/im/chain/single` → `get_play_info` → 下载原文件
6. **canvas**：React Flow 节点编辑器。
   - 节点：视频生成（模型 / 时长 / 比例 / 提示词）、图片生成、参考图 / 首尾帧输入
   - 边：数据流；运行 = 按拓扑把任务提交给 scheduler
7. **downloader**：无水印原文件下载（`get_play_info` 直链即原文件）。

## 数据流

```
画布节点 → scheduler（选账号：剩余额度优先）→ executor（带该账号会话提交）
  → 轮询 vid → 下载原文件 → 结果回填节点 → quota 更新该账号剩余额度
```

## 安全 / 边界

- Cookie / 账号凭证加密存储；绝不进聊天记录、日志、仓库
- 不做账号批量注册、不绕过验证 / 风控（硬边界，用户 2026-10-01 起多次明确）
